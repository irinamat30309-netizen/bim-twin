# BIM TWIN — изменения review Stage 4

Stage 4 расширен до bounded/two-pass out-of-core пути для поддерживаемых **ASCII/binary PLY point clouds, uncompressed LAS point formats 0–10 и ASCII/interleaved-binary/LZF-compressed PCD**: disk scan → canonical store → disk-partitioned octree. Это всё ещё ограниченный профиль, не завершение Stage 4.

## Out-of-core ветка scalar-property PLY

- `las-node.js` распознаёт ASCII и binary little-/big-endian scalar-property PLY point clouds. Два прохода по исходному файлу анализируют XYZ/bounds/axis и записывают canonical records (float32 viewer XYZ + uint8 RGB); ASCII читает bounded lines с CRLF/смешанными разделителями и без обязательного final newline.
- Передаётся source transform активного preview. Все индексированные точки остаются зарегистрированными с уже открытой сценой даже если sampled preview и полный source имеют немного разные bounds.
- `octree-build-core.js` не материализует полный `pos[]/col[]` набор: строит node representatives в ограниченном рабочем буфере, пространственно записывает остальные точки в временные partition-файлы и рекурсивно потребляет их. Финальный store содержит `nodes.bin` + `index.json`; scratch удаляется после сборки.
- `main.js` распознаёт поддерживаемые PLY/LAS/PCD профили до worker, берёт authoritative header/point count/layout вместо доверия renderer-счётчику и использует отдельные RAM/disk preflight модели. Worker сверяет fingerprint источника с открытым fd; изменённый после preflight файл отклоняется до conversion.
- Не поддерживаются как out-of-core PLY mesh, list-valued properties, vertex element не первым и layouts вне scalar profile; compressed LAS/LAZ и другие форматы пока не получают этот claim.
- LOD nodes пока содержат XYZ/RGB; пропуск intensity/classification явно показывается. UI обновляет общий текст прогресса для LAS/PLY/PCD scan/conversion/disk partition и сообщает ограничения.

## Uncompressed LAS out-of-core branch

- Добавлен bounded двухпроходный `prepareLasOctreeFile`; indexer поддерживает uncompressed LAS PDRF 0–10 с проверкой минимальной длины record, version/PDRF совместимости, positive finite scales, point-data bounds и LAS 1.4 extended point count. Прореживание детерминировано, глобальная точность сохраняется через double offset до преобразования viewer XYZ в Float32.
- RGB16/8 по sample depth преобразуется в RGB8 canonical node format; если RGB отсутствует/все нулевые, остаётся высотная рампа. CRS WKT читается из ограниченных VLR/EVLR, source transform/CRS, class/intensity presence и omissions фиксируются в `index.sourceMeta`.
- Compressed/unknown flags, усечённые LAS и stale source fingerprint отвергаются до commit. `parseLASFile` тоже больше не интерпретирует compressed LAS как обычные records и не индексирует молча заявленный, но отсутствующий tail.
- `octree-build-core.js` обобщён для канонических LAS/PLY/PCD-records, `main.js` использует source header count для resource preflight, а UI title/progress сообщает LAS/PLY/PCD support.

## ASCII/binary/LZF PCD out-of-core branch

- Новый `pcd-out-of-core.js` проверяет header fields/types/counts, authoritative `POINTS` и соответствие `WIDTH × HEIGHT`, binary/LZF byte extent, bounded ASCII строки, metadata comments и стабильность файла по identity/layout fingerprint. Поддерживаются `DATA ascii`, interleaved `DATA binary` и PCL field-major `DATA binary_compressed`: LZF literal/back-reference stream декодируется в ограниченных чанках во временный planar store на диске, после чего нужные поля читаются bounded chunks.
- Тот же bounded LZF decoder теперь используется обычным sampled preview parser: целый decompressed payload не держится в RAM и прежний cap 512 MiB удалён. Preview заранее проверяет свободное место temp-volume, когда `statfs` поддержан, передаёт видимый byte progress, до выделения конечных typed arrays проверяет RAM-бюджет выборки (эвристика: 128 bytes/point + 128 MiB, не более 70% доступной RAM), читает только выбранные записи и удаляет личный scratch после успеха и ошибок. Async Worker владеет уникальным temp root; parent ждёт termination перед удалением при cancel, так что cleanup не зависит от worker `finally`. Для LOD scratch удаляется после успеха/ошибки в worker output scope, а main disk preflight прибавляет полный uncompressed planar size. Preview остаётся sampled in-memory view; это не full out-of-core viewer. Reader сохраняет source transform, packed/separate RGB и CRS/units metadata, считает нечисловые XYZ, сообщает пропуск intensity/classification; модуль включён в `build.files`.
- `local-only Chromium harness (not included)` прошёл видимой LOD-кнопкой на `binary_compressed` PCD с 300 000 points / 10 209 608 bytes: preview 150 000, out-of-core index 300 000 / 9 nodes, transform совпадает, UI показывает фазу `PCD LZF → временный диск`, выключение восстановило preview и очистило disk store, PAGEERROR/IPCERR/NOHANDLER — 0. Повторный прогон дополнительно подтвердил видимое сообщение `Распаковываю PCD LZF во временное дисковое хранилище`, удаление parser temp root, 0 leaked octree directories и 0 UI/IPC errors. ASCII regression проходит payload >8 MiB с CRLF и без последней newline; interleaved binary проверен Worker/unit.
- Отдельный Chromium UI/IPC cancel сценарий использовал synthetic `binary_compressed` PCD на 12 000 000 точек (compressed file 1 636 641 bytes; raw 137 MiB). Нажатие видимой кнопки «Отмена» на фазе LZF (14%, 0/137 МиБ) отправило ровно один cancel IPC, UI показал «Импорт отменён», сцена не изменилась, Worker завершился, приватный scratch удалён, PAGEERROR/IPCERR/NOHANDLER — 0. Evidence: `QA-artifacts/stage3-4-continuation/pcd-lzf-ui-cancel-e2e.json`.

## Незакрыто

PCD LZF preview и LOD освобождены от contiguous decompression buffer; sampled preview arrays всё ещё in-memory, а RAM/disk preflights являются предварительными эвристиками, не hard quotas; нет full attributes in nodes, stream-aware фильтрации/аналитики/export и persistent/restart-resumable index. PLY mesh, compressed LAS/LAZ и другие форматы вне перечисленных PLY/LAS/PCD остаются memory-bound. Worker/API cancellation и видимое нажатие UI-кнопки cancel во время LZF проверены E2E; Целевой Windows packaged/ASAR/GPU стенд, stress/pressure runs и benchmark 100 GB отсутствуют. Resource budgets — эвристические checks, не гарантии стабильности на всех машинах. Следовательно Stage 4 остаётся **частичным и не принятым**.
