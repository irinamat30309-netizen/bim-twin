# RENDER-r204 — поверхность как в Lixel: очистка + заполнение геометрии в приложении

Дата: 2026-11-27. База r203.1 (`f1728ec`). Ветка `agent/ui-redesign`.

## 0. Что нашлось в Lixel Studio

- `pluginlib/meshReconstructPlugin/meshReconstructPlugin.dll` — плагин **Mesh Reconstruction**
  («point cloud to mesh conversion»), локальный и облачный режимы.
- `XGridsMeshRecostruct.exe` + `meshReconstruct.dll` — CLI/движок построения поверхности.
- `config/mesh_config_{,high,ultra}.yaml.enc` — пресеты качества меша.
- `pluginlib/baseFilterPlugin/baseFilterPlugin.dll` — **MLS smoothing**, subsample, denoise.
- `postProcessorPlugin.dll` — `enableGenerateMesh`, `meshQuality`, `meshType`, `filterLevel`:
  Lixel при обработке скана умеет строить меш и заполнять поверхность, а не только красить точки.

Вывод: «гладкий Lixel» — это не магия рендера, а **поверхность (mesh)**, построенная по облаку.
Поэтому и у нас точки выглядели облаком, а Lixel — сплошной стеной.

## 1. Что уже было в BIM Twin

В приложении давно есть Python-сайдкар **Open3D** и команда «Геометрия → Построить поверхность
(mesh)» (`tools/pointcloud_geometry.py --mode mesh --method poisson`). Но:
- меш был **серый** — Poisson не переносил цвет точек;
- меш не открывался после построения (main-парсер не читает mesh-PLY, fallback не срабатывал);
- параметры были слабые (depth 9), без явной команды «как Lixel».

## 2. Что добавлено (r204)

1. **Перенос цвета на вершины меша** (`tools/pointcloud_geometry.py`): после Poisson/BPA цвет
   каждой вершины берётся у ближайшей точки облака (scipy cKDTree, запасной Open3D KDTree).
   Меш теперь цветной, как поверхность Lixel, а не серый.
2. **Загрузка меша после построения**: `reloadGeomCloud` читает выход через `readPicked`
   (файл авторизован main-процессом) и грузит PLY-меш рендерером; добавлен fallback для `.ply`.
3. **Одна команда**: «Облако → Геометрия → **Lixel: очистить и заполнить (поверхность)**» —
   Poisson `depth 11`, `voxel 0.04`, до 12M точек; открывает готовый цветной меш в просмотрщике.
4. **Исправлена русская локаль**: Python-сайдкар запускается с `PYTHONUTF8=1` /
   `PYTHONIOENCODING=utf-8` — иначе путь `C:\Users\...\BIM Twin Проекты\...` превращался в
   `РџСЂРѕРµРєС‚С‹` и меш падал с «No such file». Теперь работает на русских путях.

## 3. Проверка

- Прототип на нашем фасаде: 22,4M точек → Poisson depth 11, voxel 4 см →
  **1 292 452 вершины / 2 579 176 треугольников**, цветной PLY 52,9 МБ
  (`_scratch/r204/facade_mesh_yup.ply`).
- Сквозная проверка в приложении на тестовом облаке: meshCloud → 228 747 вершин / 457 000
  треугольников → `reloadGeomCloud` = **true**, меш открылся в просмотрщике.
- Команда доступна в меню «Геометрия облака»; для работы нужен Open3D (в приложении —
  «Установить Open3D + SciPy», ставится изолированный Python 3.12).
- `node --test --test-concurrency=1`: **1959 тестов / 1955 pass / 0 fail / 4 skip**.

## 4. Ограничения

- Poisson строит поверхность по **всему bbox**; для длинного скана глубина 11 даёт ~10–15 см
  на весь bbox. Для максимальной детали надо резать область/повышать depth — это следующий шаг
  (авто-кроп по плотности).
- Меш «затягивает» мелкие дыры и шум; для инженерных обмеров его нельзя использовать вместо
  облака — это визуальный слой «как Lixel». Облако остаётся исходным.
- Построение на 10–20M точек занимает минуты и требует RAM; на 594M напрямую — нельзя,
  поэтому перед Poisson берётся выборка/воксель.

## 5. Итог

Приложение теперь умеет **само** построить цветную поверхность по новому скану и заполнить
геометрию: «Геометрия → Lixel: очистить и заполнить (поверхность)». Это тот же класс результата,
что делает Lixel Studio (mesh reconstruction), а не просто точки с фильтром.
