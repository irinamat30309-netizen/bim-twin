# Повторная проверка — review v10.1

## Объём и среда

Проверен один ограниченный этап: точное mesh-сечение по X/Y/Z, его отмена/жизненный цикл, превью и DXF R12 экспорт на двух пользовательских геометриях. Среда — Linux, Node.js 24, Playwright/Chromium с WebGL SwiftShader и fake-Electron harness; это не собранный production installer и не целевой GPU Windows. Для приложения использован JSON store fallback: пакет `better-sqlite3` в среде отсутствует.

## Пользовательские меши

- OBJ: 36 836 365 bytes; 315 390 треугольников; в viewer 809 574 render-вершины.

## Проверки отмены и замены

Для теста отмены только в harness четыре раза повторены ссылки на primitive пользователя; исходный файл не менялся. Worker получил 1 261 560 triangle instances и около 88,5 MiB передаваемых буферов. Cancel вызван при получении progress `intersect` с ненулевым числом завершённых треугольников; Worker завершён, UI показал отмену, повторный расчёт остался доступен.

В отдельном сценарии при таком же усилении начат расчёт и вызвана замена на реальный STL. API загрузки завершил section Worker до результата; новый меш загрузился (315 495 треугольников), а старая панель и состояние progress/cancel сбросились. Это проверка управления жизненным циклом, не стресс-бенчмарк ресурсоёмкости.

## Ограничения

- Защитный предел — 2 млн треугольников и 128 MiB копий. Если Worker отсутствует, fallback синхронен только до 20 тыс. треугольников.
- DXF R12 хранит локальные координаты плоскости и флаг замкнутости, но не CRS/units. Независимое открытие CAD не проверено.
- Превью сечения — накладной контур; оно не физически вырезает меш, не строит срез-поверхность и не является depth-tested CAD viewport.
- Сечение mesh дополняет, но не заменяет растровое сечение point cloud; mesh не строится автоматически из облака.
- Не проверялись Windows package/ASAR, производственная видеокарта, RAM/VRAM и большие исходники выше лимитов.
- Полная профессиональная готовность не достигнута. По дорожной карте этап 1 остаётся частичным, этапы 2–14 не закрыты.
