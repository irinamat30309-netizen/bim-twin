# BIM TWIN — изменения review Stage 3

Этот инкремент укрепляет ядро импорта/экспорта облаков, сохранение исходной системы координат и честное отображение возможностей форматов. Проверены multi-scan PTX import/export, per-scan poses и безопасная потоковая commit-проверка. Этап 3 **не считается полностью принятым**: список поддерживаемых, частичных и неподдерживаемых сценариев приведён ниже и в `QA-RETEST-stage3.md`.

## Импорт и экспорт облаков

- В desktop-пути доступны LAS, PLY-cloud, E57, PTX, PCD, PTS, XYZ и CSV; для LAZ предусмотрен отдельный optional decoder. PTX importer читает последовательные сканы, проверяет размеры сетки, отбрасывает отсутствующие 0/0/0 returns, применяет матрицу сканера и сохраняет RGB/intensity и scan metadata; отображение объединено. PTX writer теперь сохраняет contiguous scan grouping, исходные матрицы и rigid poses при валидных диапазонах точек, записывая каждый scan как одну строку. Исходные grid dimensions и missing-return cells не восстанавливаются. Browser fallback дополнен E57 и ограниченной выборкой точек.
- E57 reader/writer работает с бинарным ASTM E57, физическими страницами и CRC, XML-описанием и CompressedVector-пакетами. Reader учитывает несколько сканов, позы, сферические координаты, invalid-state, RGB/intensity и лимит выборки. Writer сохраняет XYZ, RGB, intensity и WKT `coordinateMetadata`; при непрерывных актуальных scan ranges сохраняет разбиение, имена и rigid poses как для одного, так и для нескольких scans. Если edits сделали ranges несовместимыми с текущим массивом точек, preflight предупреждает, а экспорт безопасно объединяет набор в один scan.
- Исправлено кодирование E57 XML CDATA: исходные `&`, `<`, Unicode и `]]>` в scan names/CRS round-trip без подмены текста и повреждения XML. Мини-XML parser корректно декодирует числовые ссылки за пределами BMP и отклоняет запрещённые XML code points; усечённый CDATA/comment/processing instruction/tag и несогласованные скобки теперь дают понятную ошибку вместо зависания.
- Viewer больше не перемешивает порядок точек при adaptive-render optimization, если присутствуют E57 scan ranges: раньше для массивов >2 млн это могло назначить точки не той станции; обычные clouds без scan metadata сохраняют shuffle-оптимизацию.
- LAS export формирует LAS 1.4, point data record format 7, с 16-bit RGB/intensity, 8-bit classification и WKT VLR. PLY writer записывает double XYZ при больших координатах и BIM TWIN metadata comments.
- PCD ASCII и binary/LZF-пути проверяют структуру полей, размеры, число точек, усечённые и лишние данные. Обычный preview `binary_compressed` больше не материализует целый raw buffer: LZF декодируется bounded-чанками во временное planar disk store, из которого создаётся только выборка по настроенному point budget. Проверяются свободное место на временном томе где доступно, монотонный прогресс и удаление scratch при успехе, malformed data и worker cancellation. Preview и дальше хранит sampled typed arrays в памяти и не является полным disk-backed viewer.
- Текстовый импорт покрывает PTS/XYZ/CSV и варианты именованных XYZ/RGB/intensity/classification полей. В меню экспорта добавлен CSV с заголовком полей и BIM Twin comment metadata (up-axis/units/CRS URI), включая RGB/intensity/classification при наличии. Round-trip XYZ/RGB/intensity/classification/units/WKT и flatten-warning для multi-scan покрыты тестом. Generic spreadsheet readers могут игнорировать комментарии; export остаётся плоской таблицей и не сохраняет scan grid/poses.
- Capability registry отдельно обозначает поддерживаемые, частичные и неподдерживаемые форматы; export preflight отклоняет несогласованное число точек, короткие атрибуты и нечисловые значения, а потери стандартных форматов выдаёт как warnings.
- PTX проверен на синтетической multi-scan выборке: row-vector матрица PTX и column-vector affine variant, translation, missing returns, RGB/intensity, truncation и пустой scan покрыты тестами; тот же путь повторно проверен через Worker и desktop UI. Реального сканерного PTX-образца в этой проверке не было.
- PTX writer проверен отдельным commit/round-trip E2E для single scan: исходные world XYZ/RGB/intensity, atomic replacement/backup и cleanup. Новый multi-scan UI E2E экспортировал две PTX scan-группы с row-vector и column-vector transform в PTX; повторный импорт подтвердил диапазоны `[0,3]` и `[3,1]`, точные XYZ/RGB/intensity. Из той же активной сцены экспортирован E57; независимый `pye57 0.4.19` прочитал два scan data blocks и проверил координаты и атрибуты, а внутренний E57 reader проверил имена/ranges. Для stream validator добавлена поддержка десятистрочных заголовков последовательных scans, согласование grid sizes с total point count и тесты границ chunks.
- Multi-scan E57 повторно проверен от UI до файла: два источника с translation и 90° rotation импортированы и экспортированы через Smart Save. Внутренний reader и независимый `pye57/libE57Format 0.4.19` подтвердили два scan names, poses и исходные world XYZ. Внешний пакет установлен только во временную `/tmp` test target; он не стал зависимостью приложения.
- Дополнительный E57 edge-case файл с двумя сканами, именами/metadata, содержащими XML-special characters и CDATA terminator, прочитан независимым `pye57 0.4.19`: exact scan names и XYZ сохранены.
- Single-scan E57 с ненулевой translation и 90° pose прошёл unit round-trip, сквозной UI/Smart Save и независимый `pye57`: сохранены имя, pose и world XYZ. Отдельный viewer regression на 2 000 001 точке подтверждает защиту порядка для scan ranges и сохранение shuffle для обычного облака.
- Source-frame преобразования и WKT сохраняются для проверенных LAS/E57/PLY/PCD/XYZ/CSV сценариев. Реального преобразования координат между EPSG или вертикальными datum этот слой не выполняет.

## Большие облака и защита от отказа renderer

- Стандартный лимит первичной загрузки снижен до 3 млн точек, чтобы большой исходник не пытался сразу создать неограниченный GPU/renderer-буфер. Ползунок и настройка позволяют изменить point budget; смена значения повторно читает активный point-cloud файл.
- В локальном smoke крупный внешний PLY проверен с point-budget preview; точные метаданные/файл не публикуются. Это проверка устойчивости и выборки, а не обещание отрисовки полного источника или production benchmark.

## Итоговый статус

Обмен основными point-cloud форматами стал проверяемым, а неизвестная или неподдержанная функциональность больше не обозначается как успешная реализация. PTX multi-scan pose/grouping round-trip улучшен, но grid/missing-return reconstruction и другие перечисленные блокеры не закрыты: Stage 3 остаётся частичным. Для границ форматов, воспроизводимых команд, численных допусков и незакрытых приёмочных критериев см. `QA-RETEST-stage3.md` и `MARKET-FEATURE-MATRIX.md`.
