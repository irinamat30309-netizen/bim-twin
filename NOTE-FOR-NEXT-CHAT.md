## 2. Ключевая гипотеза, почему «не как Lixel»

Lixel Studio показывает облако **не как отдельные 1-px точки**, а как плотный «splat»/LOD-рендер с плавным размером точки по глубине, агрегацией подпиксельных точек и, вероятно, 3DGS/LOD-структурой. Наш вьюер:
- точек в GPU 300M из 596M (равномерная выборка по всему облаку — **на близком плане плотности не хватает**);
- точки квадратно-жёсткие, аттенюация отключена в «Классическом» профиле;
- нет view-dependent density (подгружать приоритетно точки рядом с камерой).

**Идея решения (проверить в первую очередь):**
- (а) мягкие энергосберегающие сплаты **+** perspective attenuation одновременно (сейчас в профилях они разнесены);
- (б) view-dependent LOD: при зуме показывать больше точек в текущем фрустуме (например, подгружать чанки/сегменты в камерной близости, а дальние — грубее), а не равномерную выборку;
- (в) сглаживание цвета на экране (медиана цвета ближайших точек в screen-space) — убирает хроматический шум старого recolor, не мыля геометрию;
- (г) вариант «Ultra»: полный файл в GPU при достаточной VRAM (383M+) + большая точка при близком зуме.
