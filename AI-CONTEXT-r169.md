# AI-CONTEXT-r169 — ИИ понимает контекст приложения, намерения и «Что это?»

Статус: **реализовано и проверено**. ИИ-ассистент теперь отвечает по структурированному контексту приложения
(облако, выделение, распознанный элемент, инспектор, измерения, модель, проект, документы), понимает русские
и украинские намерения локально (без API), а «Что это?» в инспекторе/панели определяет тип элемента по
выделению через классификатор auto-measure и открывает карточку в чате. Мои тесты — **104/104** (r169 24 + регрессии ИИ 80);
полный `node --test` — **1847 тестов / 1840 pass / 3 fail / 4 skipped**, причём все 3 падения — во внешнем
`test/auto-measure-r169.test.js` (классификатор phase4-edit-core ещё в работе у соседа; файл не мой и не менялся;
эти тесты падают и отдельно, вне общего прогона). Не коммитил; файлы editor-basics/phase4 (`app.js`,
`auto-measure.js`, `lixel-object-inspector.js`, `webgl-viewer.js`, `INSPECTOR-UI-r169.md`) не трогал.

## 1. Структурированный контекст приложения (`renderer/ai-context.js`, новый)

До r169 в модель уходил только текст вопроса; `ctx` был набором функций для инструментов. Теперь перед запросом
собирается `ai-context/1` (только чтение состояния, без побочных эффектов; отсутствующие данные — `null/[]`,
никаких придуманных чисел):

| Домен | Что собирается | Источник в приложении |
|---|---|---|
| `cloud` | открыто/нет, имя, путь, точек (loaded/source), bbox+габариты, СК/CRS, режим цвета, классификация, шаг точек | `__pcTools.getCloud()` (r169: sample для потокового облака), `viewer.bbox`, `_cloudRecord`, `getSourceCrs` |
| `selection` | активность, число точек, bbox/габариты, центр, объём bbox, доминирующий класс (ASPRS: 2 пол, 6 стены, 5 растительность, 18 люди) | `viewer._sel`, `viewer._classificationLabels` |
| `element` | тип/название/уверенность, размеры, нормоконтроль, источник | инспектор `__lxObjectInspector.state.auto.res`, `ElementIdentify`, auto-measure по выделению |
| `inspection` | контроль геометрии: стены/вне допуска, пол FF/FL/мм/м/площадь, дефекты, проёмы, помещения, MEP, сверка с DXF, список проверок | `CloudInspectUI.current()` (r34-мост для ИИ) |
| `model` | BIM-модель: этажи, стены, проёмы, помещения, плиты, трубы/балки/объекты, материалы, длина стен | `__lxScan2BIM.state.model`, `__lxScan2BIMAI.getModelSummary()` |
| `project` / `documents` | проект, ревизия, документы проекта, документы базы норм | `BimProjectState.snapshot()`, `__bimProjectName`, `state.norms` |
| `measurements` | последние сохранённые измерения | `BimProjectState.snapshot().measurements` |
| `tool` | активный инструмент/режим правки/черчение/выбор | viewer, `__lxModes`, `__lxDraw`, `__bimPick` |
| `checks` | проверки/вердикты инспектора (для ответов «что не так») | `CloudInspectUI.current().res` |

Функции: `build(env)`, `toPromptBlock(ctx)` (текстовый блок фактов для локальной модели с правилом «чего нет —
не выдумывай, скажи «не знаю»»), `compact(ctx)` (короткий JSON ≤2 КБ для запроса), `analyzeSelection(env)`
(классификация выделенных точек через `AutoMeasure.analyze`, fallback — метки классов облака),
`elementFromAuto/elementFromIdentify/elementFromInspector`, `summarizeRes`.

## 2. Локальный интент-парсер (`renderer/ai-intent.js`, новый)

`parse(text)` → `{intent, confidence, params, actions}`; `execute(parsed, ctx)` → ответ **только по фактам**
контекста; если данных нет — честное «Не знаю — …» + ближайшие доступные действия (без выдумывания).
Понимает русские и украинские фразы:

| Намерение | Примеры | Параметры |
|---|---|---|
| `element.type` | «что это за элемент», «это стена?», «это труба?», «що це таке?», «это стіна?» | ожидаемый тип |
| `element.measure` | «какая толщина», «какая высота потолка», «чему равна длина стены», «какой диаметр трубы», «сколько площадь», «яка товщина стіни?» | тип размера + тип элемента |
| `selection.measure` | «покажи размеры выделенного», «измерь выделенное» | — |
| `find` | «найди двери», «покажи окна», «сколько дверей», «где трубы», «найди стены вне допуска», «знайди двері» | цель + фильтр (вне допуска) |
| `compare.docs` | «сверь с документацией», «проверь по проекту», «соответствует ли стена проекту», «звір з документацією» | документ |
| `document.build` | «построй документ», «сформируй отчёт», «сделай исполнительную документацию», «побудуй документ» | тип документа |
| `norms.lookup` | «какой допуск вертикали по СП 70», «какая норма для толщины» | документ |
| `calculate` | «посчитай 12,5 на 3,2», «сколько будет 4 на 5» | выражение/результат |
| `model.info` / `checks.summary` / `project.info` / `help.*` | «что в модели», «итоги проверки», «какие дефекты», «что за проект», «что ты умеешь» | — |
| `unknown.meta` / `unknown` | «не знаю что это» / всё остальное | — |

Действия структурированы (`{kind:'pick-element'|'analyze-selection'|'open-inspection'|'open-docs'|'open-norms'|'open-model'|'find'}`)
и исполняются только безопасные (открытия/выбор/анализ); опасные операции по-прежнему требуют подтверждения.

## 3. Интеграция в `renderer/ai-assistant-ui.js`

- **Контекст в запрос:** в `ask()` перед `BimAssistant.runAgent` собирается `appPack()`, и вопрос обогащается
  блоком `toPromptBlock` (облако/выделение/элемент/инспектор/модель/документы + правило «не выдумывай»).
  В `makeCtx()` добавлены `appContext/appContextBlock/appContextCompact/selection/element/analyzeSelection/
  parseIntent/executeIntent/modelSummary/checks` — модели и инструментам доступны и структура, и текст.
- **Локально-первые ответы:** фактические вопросы (`element.type/measure`, `find`, `checks.summary`, `model.info`,
  `project.info`, `calculate`, `unknown.meta`) отвечаются локальным парсером по контексту без модели — быстро,
  детерминированно, офлайн; для остальных при готовой модели — запрос с контекстом, при недоступной — честный
  локальный ответ (в т.ч. без загруженного модуля ассистента).
- **«Что это?» по выделению:** `explainSelection()` берёт выделенные точки, классифицирует `AutoMeasure.analyze`,
  показывает тип/размеры/уверенность/нормоконтроль; при готовой модели дописывает объяснение с тем же контекстом.
- **«Что это?» по щелчку:** исправлен гейт — в потоковом/большом облаке `getEditedCloud()` намеренно `null`,
  теперь берётся буфер `viewer.base[0]` (sample), поэтому «Откройте облако точек» больше не появляется при
  открытом облаке. Работают оба классификатора: `ElementIdentify` — основа карточки, `auto-measure` — уточнение;
  при расхождении типов честно показывается, что предложил каждый.
- **Инспектор → ИИ:** публичный мост `window.__lxAiWhatIs(element?)`, событие `lx-ai-what-is` (detail.element/
  detail.auto), делегирование клика по `[data-ai="what-is"]`/`[data-ai-explain]`/`#lxAskWhatIs`; элемент
  можно не передавать — возьмётся последний `auto.res` инспектора. Файлы инспектора не правил.
- **`scan2bim-ai-client.js`:** в запрос реконструкции на AI-сервер добавлен `context` (JSON `ai-context/1`:
  облако/проект), экспортированы `getContext()` и `getModelSummary()` (этажи/стены/проёмы/помещения/трубы/балки),
  которые использует контекстный модуль.

### Найденные баги и исправления (r169)

1. **Ложный гейт «Откройте облако точек»** у «Что это?» на потоковом облаке: `getCloudArr`/`getEditedCloud()`
   возвращали `null` → fallback на `viewer.base[0]`/`__pcTools.getCloud()` sample.
2. **Уверенность >100 %** в карточках auto-measure → нормализация score в 0…100 %.
3. **Сырые числа размеров** («Ширина проёма — 3.9999665989535362») → округление/единицы/подписи в нормализаторе.
4. **Толщина стены у проёма** («Глубина проёма (толщина стены)») не находилась по `key` → поиск и по подписи размера.
5. **Офлайн без модуля ассистента** показывал «модуль не загружен» вместо честного ответа → локальный парсер
   теперь отвечает и в этом случае.
6. **Расхождение классификаторов** при щелчке (ElementIdentify «Стена» и auto-measure «Труба») → основа —
   ElementIdentify, расхождение показывается явно, без выдачи одного за другой.

## 6. Ограничения

1. Локальный парсер покрывает прикладные намерения (элемент/размеры/поиск/сверка/документы/нормы/расчёт/модель);
   свободные вопросы уходят модели, если она установлена, иначе — честное «не знаю» + действия.
2. Точность 100 % измерена на наборе из 48 курируемых фраз; на произвольной речи возможны вариации (парсер
   консервативен: сомнительное → `unknown`, не выдумывает).
3. Классификация выделения зависит от геометрии `AutoMeasure` (сложные/смешанные выделения могут дать
   расхождение с ElementIdentify — показываются оба варианта); для «что это» лучше выделять один элемент.
4. Факты о документах/нормах — только по загруженным документам и базе норм; пустая база = честное «не знаю».
5. Модель (Ollama/Qwen) не входит в пакет; без неё работает локальный режим. Установка модели не требовалась.
