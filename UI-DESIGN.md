# BIM Twin — дизайн-система интерфейса

Документ описывает оболочку приложения, появившуюся в `1.2.0-rc.3`: структуру окна, дизайн-токены, компоненты, движение,
программный интерфейс `window.__lx*`, тестирование и правила расширения. Пути — от корня репозитория.

## 1. Принципы

1. **Одна кнопка — одно место.** Каждая команда живёт в одной вкладке ленты и в одной группе по смыслу. Реестр
   `renderer/ui/commands.js` — единственный источник правды: из него строятся лента, палитра команд (`Ctrl K`) и тесты.
2. **Минимализм.** Нейтральный графит + один акцент. Иконки линейные (Lucide, 24 px, штрих 1.75), без эмодзи и
   символов-картинок (`✕`, `▶`, …). Подписи — обычным текстом.
3. **Порядок вместо россыпи.** Кнопки внутри инструментов лежат в общих контейнерах (`fpanel-toolbar`, `hud-dock`,
   `lx-pop`, `modal-card`), а не поверх сцены в произвольных местах.
4. **Плавность по делу.** Анимация показывает причину и следствие (панель выезжает оттуда, где её открыли; долгая
   операция показывает прогресс), а не украшает. Длительности 120–280 мс, при `prefers-reduced-motion` анимации выключаются.
5. **Ничего нативного.** Нет `alert/confirm/prompt` (в Electron `prompt` не работает и выглядит чужеродно): вместо них
   `__lxKit.ask` и тосты. Это проверяет тест `test/ui-dialogs.test.js`.
6. **Работает без сети и без сборщика.** Шрифт Inter вшит в `renderer/ui/fonts.css` как data-URI, иконки — в
   `renderer/icons.js`. Внешних CDN нет; CSP не ослаблялась.

## 2. Структура окна (`renderer/index.html`)

```
┌ #titlebar ── панель · проект · палитра команд · помещение · тема · инспектор · окно ┐
│ #lxTabs    — вкладки ленты (11)                                                     │
│ #lxRibbon  — группы команд выбранной вкладки; сворачивается в одну строку вкладок   │
├───────────────┬──────────────────────────────────────────┬──────────────────────────┤
│ #sidebar      │ #stage — сцена (WebGL) + плавающие       │ #inspector — свойства,   │
│ дерево проекта│ панели #stageSideL / #stageSideR,        │ документы, результаты    │
│ и этажи       │ HUD-док #hudDock (измерение, правка, тур)│ (выезжает как drawer     │
│               │ навигация сцены, тосты                   │  при ширине окна ≤ 1100) │
├───────────────┴──────────────────────────────────────────┴──────────────────────────┤
│ #lxStatus — состояние облака, FPS, координаты, фоновые операции                     │
└─────────────────────────────────────────────────────────────────────────────────────┘
```

* Боковая колонка и инспектор закрываются; состояние, последняя вкладка ленты, свёрнутость ленты и режим
  «сцена/документы» запоминаются в `localStorage`.
* `#lxLegacy` — скрытый контейнер с исходными кнопками. `ribbon.js` «усыновляет» их (переносит вместе со слушателями),
  поэтому старый код `app.js` и модулей `lixel-*` продолжает работать без правок.
* Стартовый экран — отдельная страница `renderer/startup.html` (+ `startup.js/css`): карточки проектов, поиск,
  «Новый проект», настройки (тема, хранилище, версия), плавный переход в рабочую область.

## 3. Дизайн-токены (`renderer/ui/tokens.css`)

Тема задаётся атрибутом `html[data-theme="dark|light"]`; тёмная — по умолчанию. Класс `.theme-dark` заново применяет
тёмную палитру к поддереву (3D-просмотры всегда на тёмном фоне).

| Группа | Токены |
| --- | --- |
| Поверхности | `--bg-0 … --bg-4`, `--line`, `--line-strong`, `--overlay`, `--glass`, `--glass-line` |
| Текст | `--txt`, `--txt-2`, `--txt-3`, `--on-accent` |
| Акцент | `--accent`, `--accent-hi`, `--accent-fill(-hi)`, `--accent-soft`, `--accent-line`, `--accent-glow` |
| Состояния | `--ok`, `--warn`, `--err` и `*-soft` |
| Форма | `--r-1 … --r-4` (радиусы), `--shadow-1 … --shadow-3`, `--shadow-pop` |
| Типографика | `--font` (Inter → системный sans), `--mono`, `--fs-xs/sm/md/lg` (11/12/13/15 px) |
| Движение | `--t-fast`, `--t-med`, `--t-slow`, `--ease`, `--ease-in` |
| Раскладка | `--h-title`, `--h-tabs`, `--h-ribbon`, `--h-status`, `--w-side`, `--w-insp`, `--dock-h` (ставится в `chrome.js`) |
| Слои | `--z-stage < --z-hud < --z-panel < --z-drawer < --z-modal < --z-pop < --z-tip < --z-toast < --z-boot` |
| Чертёж | `--draw-*` — цвета инструментов рисования на сцене |

Старые имена (`--panel`, `--muted`, `--text`, …) оставлены как алиасы: контент `styles.css` и динамическая разметка в JS
работают без правок. **Цвета в новых стилях — только через токены**; для светлой темы отдельных правил не пишут.

### «Выбрать объект → измерить»

Кнопка **Измерить объект** (вкладка «Измерения», группа «Объект») включает выбор объекта рамкой по облаку, после чего
открывается окно «Инспектор объекта» (`#lxInsModal`): отдельный 3D-вид только с этим объектом. Слева на сцене —
режимы отображения (RGB / высота / EDL / размер точки) и виды (кадр, спереди, сбоку, сверху); справа — инструменты
замера, «Результат» и история измерений. Повторный клик по кнопке, `Esc` и «Выйти» останавливают выбор рамкой; окно
закрывается крестиком, `Esc` или щелчком по затемнению.

Справа две вкладки — «Вручную» (по умолчанию) и «Автоматически» (`#lxInsTab-manual`, `#lxInsTab-auto`; компонент `.lx-win-tabs`, роли `tablist/tab/tabpanel`);
выбор типа объекта общий и стоит над вкладками. На вкладке «Автоматически» кнопка **«Измерить автоматически»** (`#lxInsAutoBtn`) запускает
`renderer/auto-measure.js`; результат — карточки `.lx-auto-card` (главный объект и «Ещё найдено»), в строке `.lx-auto-row.high|medium|low` — размер, ±σ, способ и бейдж
`.lx-lvl` «уверенность: высокая / средняя / низкая» (цвет — токены `--ok/--warn/--err`, не только цветом: есть подпись). «Показать» рисует размер на облаке, «Сохранить» кладёт
размер низкой уверенности в проект (надёжные главного объекта сохраняются сами). Устройство и проверка — [`AUTO-MEASURE.md`](AUTO-MEASURE.md).

**Ревизия 4 — замер именно нужного объекта.** Под кнопкой «Измерить автоматически» стоит вторая, `#lxInsAutoPick` «Указать объект» (иконка `crosshair`, `aria-pressed`, подсветка `.lx-auto-pick.on`): режим точки — клик по облаку привязывает замер к объекту под курсором (точка в историю и проект не пишется). Карточка главного объекта (`.lx-auto-card`) получает метку «главный объект»; находки другого типа — «другой тип» (`.lx-auto-card.off`, приглушены, в проект сами не идут). Строка `.lx-auto-objline` «Измерено по этому объекту · N т.» с кнопкой «Показать объект» (`data-auto-outline`) рисует контур объекта поверх облака. Привязки к окружению (высота над полом) вынесены в группу `.lx-auto-grp` «Привязка к окружению — не размер объекта, сама в проект не сохраняется». Сводка (`.lx-auto-sum`) сообщает о числе отброшенных ложных находок (причины — во всплывающей подсказке), о смене типа, о далёкой точке («возможно, это не тот») и при нескольких типах без выбора даёт подсказку `.lx-auto-sum.hint`; если объекта выбранного типа в рамке нет, показывается `#lxInsAutoNoMatch`.

**Ревизия 5 — вкладка «Измерения».** В режимах после «Площади» стоит кнопка `#mmDiameter` «Диаметр» (`data-mm="diameter"`, иконка `diameter` — окружность с диагональным диаметром и стрелками на концах, переключатель как у остальных режимов; зарегистрирована в `commands.js` и `ribbon.js`): один клик по трубе даёт ось и радиус по всей видимой дуге, значение «Ø …» в окне результата и в списке замеров. Метка у курсора перед вторым кликом совпадает с числом в окне («Ø 22,0 см», «2,800 м ⊥»); у плоскостных пар отрезок на сцене перпендикулярен. Клавиши: **Esc** — отмена начатого замера (слой в `lixel-workspace`, выше закрытия окон), **Backspace** и **Ctrl+Z** — последняя точка, **Enter** — завершить ломаную или площадь. «В список» не сохраняет неготовый замер и подсказывает, что кликнуть дальше; «Очистить всё» при двух и более замерах требует второго нажатия в течение 4 с (подсказка-тост).

### Измерение с привязкой

В режиме «Измерения → Расстояние» включена **«Привязка»** (`#mmSnap`, переключатель в ленте; по умолчанию включена). У курсора —
подсказка `.meas-snap-tip` (классы `k-corner|edge|plane|point`, `q-high|medium|low`): «**Ребро** · 2 плоскости · по 2 633 точкам · шум 1,2 мм · ±1,4 мм».
Сначала стоит «уточняется…», через ~0,15 с плоскости вырастают на всю поверхность и метка доезжает до точного положения; слабый угол
подписан «оценка грубая» и красится цветом ошибки. Рядом с курсором работает лупа `.meas-loupe`. На сцене у отрезка между параллельными
плоскостями или рёбрами метка с «⊥»; в панели результата — «между плоскостями (по нормали)» / «между рёбрами (по перпендикуляру)», ±σ и, если
плоскости не параллельны, строка «не параллельны на 1,9°: значение зависит от места (3,3 мм на 10 см)». Если пара не сводится к плоскостям или
рёбрам (обе точки на одной кромке, ребро и угол), панель показывает обычное 3D-расстояние, а ±σ — только когда обе точки определены полностью
(угол, точка облака): у ребра и плоскости погрешность есть лишь поперёк них. Алгоритм, границы и проверка на реальном скане — в
[`PRECISION-SNAP.md`](PRECISION-SNAP.md).

### Окно «Сверка с документацией»

Кнопка **Сверка с докум.** (вкладка «Измерения», группа «Сверка»; также «Контроль → Замеры и докум.») открывает окно `#lxVerify`
(`renderer/ui/verify.js`, `verify.css`). Логика сверки остаётся в `app.js` и `measurement-doc-compare.js` (мост `window.__lxDocCheck`), окно
только показывает и вызывает её. Две вкладки:

* **Измерения** — таблица: измерение, требование из документов помещения, факт, отклонение, статус. Фильтры по статусам со счётчиками
  («Все», «В допуске», «Отклонения», «Проверить», «Нет в документах»); строка раскрывается: кандидаты с причинами и источником (файл,
  страница или строка) и «Принять»; кнопка «Принять предложения (N)» подтверждает все однозначные. Если в файле облака не указаны
  единицы, сверху плашка с выбором единиц: без них числа не сравниваются.
* **Найдено в документах** — все размеры и допуски, которые удалось прочитать из документов помещения, с источником. Внизу блок
  **«Свои размеры»**: название объекта, размеры (ширина, высота, толщина, длина, диаметр…) с единицами и допуском, «Добавить размер»,
  список «Ваши размеры» (хранится вместе с помещением и участвует в сверке как ещё один источник). В раскрытой строке измерения —
  **«Сравнить со своим размером»**: ввести число и допуск → «В допуске: замер 905,0 мм, разница 0,0 мм» или «Отклонение…». Пустые названия,
  нули и мусорные допуски («abc», «1 мм») отклоняются с подсказкой, а не считаются «допуск не задан».

Сценарии `verify*` стенда `dev/ui-lab` (`panels.js`) проверяют пустое окно, заполненную таблицу, раскрытую строку, фильтры, «Принять»,
«Свои размеры» и сравнение со своим размером — с проверкой результата, а не только снимком.

Текст, обрезанный многоточием (название требования, источник, подписи счётчиков и фильтров), получает подсказку с полным текстом: `tipClipped()` в
`verify.js` ставит `title` только тем элементам, которым не хватило места, и снимает его, когда после изменения ширины окна текст помещается
(пересчёт при каждой перерисовке окна и при `resize`). Сценарий `verifytip` проверяет подсказку и её показ при наведении; правило аудита `CLIPPED-TEXT`
ловит такие места на ширине 1024 px.

### Обработка облака (ревизия 6)

Группа «Обработка» вкладки «Облако»: «Ресэмплирование», «Подавление шума», «Сглаживание», «Выровнять поверхности» (затем «Выровнять пол/стену», «Объединить», «Наложение»). Параметры каждой операции
запрашивает общий диалог `__lxKit.form` (`.lx-form-body/-row/-lbl`: подпись слева, поле справа, единицы и подсказка, строки с `showIf` скрываются по выбору, `Enter` — применить, `Esc` — отмена);
значения по умолчанию подбираются по облаку (шаг точек, оценка шума). Сам расчёт идёт в фоновом потоке (`renderer/cloud-process.js` → `cloud-process-worker.js`) и показывает окно прогресса
`__lxProgress.begin(label, { onCancel })`: фаза, процент, кнопка «Отмена»; `Esc` тоже отменяет, облако при этом не меняется. Результат применяется через `__pcTools.loadCloud`, `Ctrl+Z` (`__undoKeys`,
работает в любой раскладке и вне режима выделения) возвращает предыдущее облако (1–3 копии в зависимости от размера). Выбор доли точек файла — select в «Настройки → Облака точек» и `#qShare` в панели «Вид облака»;
панель свойств облака показывает «31 550 (25 %)» и заметку о доле.

## 5. Движение и загрузка

* Открытие/закрытие: панели и drawer'ы выезжают по оси, к которой прикреплены (`transform` + `opacity`, без анимации
  геометрии); меню/диалоги появляются с лёгким масштабом от якоря. Всё описано в `renderer/ui/motion.css`.
* Загрузка: сплэш `#workspaceBoot` при первом входе, тонкая полоса `#lxTopProgress` для фоновых операций, `.btn.busy`
  для действий кнопки, `.lx-skel` вместо пустых списков, плавное затухание стартового экрана перед переходом.
* Длительные операции регистрируются через `const a = __lxKit.activity('Подпись'); a.set(0.4, 'Текст'); a.done();`.
* Когда что показывать: короткое действие (меньше ~0,4 с) не рисует ничего, кроме состояния кнопки; модальная карточка
  `__lxProgress.begin(...)` появляется только через 0,4 с и остаётся не меньше 0,45 с, чтобы не «мигать»; пока доля
  неизвестна — бегущая полоса, дальше процент, прошедшее и оставшееся время; полоса `#lxTopProgress` для фоновых операций
  появляется через 0,3 с; скелетоны — только вместо пустых списков и экранов, а не на кнопках.
* `prefers-reduced-motion: reduce` отключает анимации; функциональность не зависит от анимации.

## 7. Как расширять

**Новая команда ленты**

1. Добавьте запись в `renderer/ui/commands.js`, в нужную группу нужной вкладки:
   ```js
   I('myCmd', 'ruler', 'Моя команда', { call: '__lxMyModule.run', args: [{}], needs: 'cloud', tip: 'Что делает', keys: 'Ctrl M' })
   ```
   Для существующей кнопки укажите `sel: '#id'` вместо `call` — она будет перенесена в ленту вместе со слушателями.
   Кнопку, которую создаёт другой модуль, отдайте через `slot` и `__lxRibbon.mount('myCmd', element)`.
2. Иконка должна быть в `renderer/icons.js` (см. ниже). Тест `test/ui-system.test.js` проверит, что имя существует,
   что id уникальны и что подпись не содержит эмодзи.
3. Если команда включает режим сцены, добавьте её в `MODE_TOOLS` (`renderer/ui/ribbon.js`) и вызывайте
   `__lxModes.begin/release`, чтобы режимы не накладывались.

**Новая иконка**: используйте её имя Lucide в `data-ico="…"`, `ico:'…'` или в реестре команд и выполните
`node tools/build-ui-icons.mjs --lucide <каталог lucide-static/icons>` — скрипт сам находит используемые имена в
исходниках и пересобирает `renderer/icons.js`; `--check` сообщает, актуален ли файл (без каталога Lucide проверяет только,
что все имена есть в `icons.js`). Пакет-источник: `npm pack lucide-static@1.48.0`.
**Шрифт**: `node tools/build-ui-fonts.mjs --src <папка с inter-*-wght-normal.woff2>` (пакет `@fontsource-variable/inter`,
каталог `files/`) пересобирает `renderer/ui/fonts.css`; `--check` проверяет готовый файл.

**Диалоги вместо `prompt/confirm`**: `const v = await __lxKit.ask({ title:'Класс LAS', input:true, type:'number', min:0, max:255,
validate: v => v === '' ? 'Введите число' : null });` — `null` означает «Отмена».

## 8. Проверка

* `npm test` — полный набор (для интерфейса: `ui-system`, `ui-commands`, `ui-modes-behavior`, `ui-dialogs`, `ui-startup`, `ui-verify` —
  source-level и `vm`, без браузера; для захвата — `precision-snap`: синтетическая комната с шумом лазера). `node scripts/check-syntax.mjs` — синтаксис всех JS/MJS/CJS.
* `dev/ui-lab` — визуальный стенд (Playwright + Chromium, заглушка `bimAPI`): обход вкладок, панелей, меню, диалогов,
  тостов, прогресса, стартового экрана в тёмной и светлой темах при 1024–1920 px. Функция `audit` в `lab.js` после
  каждого сценария ищет дефекты раскладки: `MISSING-ICON`, `CLIPPED-TEXT`, `CLIPPED-CONTROL`, `OFFSCREEN`, `SIDE-OVERFLOW` (содержимое боковой колонки шире неё), `SMALL-TARGET` (цель меньше 24×24 px и задевает соседнюю, WCAG 2.5.8), `OVERLAP`,
  `DEFAULT-STYLE` (системная рамка вместо стиля дизайн-системы), `NO-NAME` (кнопка без подписи), `PAGE-SCROLLED`, `PAGE-OVERFLOW`.
  Описание запуска — `dev/ui-lab/README.md`.

## 10. Ограничения

* Проверка интерфейса выполнена в Chromium со SwiftShader и заглушкой IPC; реальный Electron на Windows с GPU и
  файловыми диалогами ОС в этой среде не запускался.
* Новые подписи интерфейса (лента, диалоги, стартовый экран) — на русском; переключение языка (`i18n.js`) их не переводит.
* Установщик `.exe` собирается только в GitHub Actions (`windows-package-qa`); в Linux-среде он не собирается.
