# BIM Twin — десктоп-приложение (offline-first)

3D-графика помещений + привязанная документация + АИ-проверка соответствия модели документам.
Стек: **Electron** + чистый JS-рендерер 3D на canvas + **SQLite / JSON**-хранилище + Python для АИ.

## Запуск

```bash
# вариант 1 — без компиляции (JSON-хранилище, работает всегда)
npm install --omit=optional
npm start

# вариант 2 — с нативным SQLite (нужен C++ build toolchain)
npm install
npm run rebuild
npm start

# сборка установщика
npm run dist        # текущая ОС
npm run dist:win    # Windows NSIS
```

Браузер-демка (без сохранения): откройте `renderer/index.html`.

## Автоматическая сверка измерений с документацией

1. Откройте помещение и, если возможно, выберите строительный элемент.
2. Выполните измерение по облаку точек и нажмите **«В список»**.
3. BIM Twin в фоне читает связанные PDF/DOCX/XLSX/CSV/TXT/DXF, при необходимости запускает локальный OCR, извлекает только размеры с явными единицами и ранжирует требования по элементу, типу объекта, оси размера и текстовому контексту.
4. Однозначное совпадение с подтверждёнными метаданными единиц сохраняется автоматически. В списке сразу появляется статус: соответствие, отклонение либо отсутствие допуска.
5. Неоднозначные, OCR- и сокращённые источники не получают автоматический вердикт. Кнопка **«Сверить»** показывает рейтинг, причины, предупреждения, три лучших варианта и исходную страницу/строку для проверки.
6. **«Сверить всё»** повторно обрабатывает весь список. После загрузки, сохранения или удаления документа измерения его помещения пересчитываются автоматически.
7. Окно **«Сверка с докум.»** (вкладка «Измерения») собирает всё в одну таблицу: измерение, требование из документов, факт, отклонение, статус; фильтры по статусам, «Принять предложения» для однозначных совпадений.
8. Нужного размера нет в документах? Добавьте его сами: вкладка «Найдено в документах» → блок **«Свои размеры»** (название объекта, размер, единицы, допуск). В раскрытой строке измерения кнопка **«Сравнить со своим размером»** сразу показывает «В допуске» или «Отклонение» и разницу; размер можно запомнить в списке «Ваши размеры». Пустые названия, нулевые размеры и неразборчивые допуски («abc», «1 мм») не принимаются.

Для точного подбора используйте название вроде «ширина стены А-1» либо привязывайте измерение и документ к одному элементу. Линейные и площадные результаты автоматически подтверждаются только при наличии распознанных единиц в метаданных облака. Значение без указанного в документе допуска сравнивается численно, но не помечается как прошедшее/не прошедшее.

## Точные измерения по облаку

В режиме «Измерения → Расстояние» включена **«Привязка»**: курсор ищет рядом угол, ребро, плоскость или кромку проёма, вписывает плоскости в облако и
растит их по всей поверхности, так что точка ложится на настоящий угол, а не на шумную точку скана. Расстояние считается по смыслу: стена–стена и
пол–потолок — по нормали, ширина проёма — по перпендикуляру между рёбрами. У курсора видно тип привязки, число точек и погрешность
(«Ребро · 2 плоскости · по 2 633 точкам · шум 1,2 мм · ±1,4 мм»); если плоскости не параллельны (откосы расходятся на 1–2°), панель говорит, что значение
зависит от места. Как это устроено, на каких данных проверено и где границы — [`PRECISION-SNAP.md`](PRECISION-SNAP.md).

Ревизия 5 (вся вкладка «Измерения»): курсор больше не лагает на больших облаках (кэш выбора точки и статичной сцены, индекс привязки строится порциями); труба меряется по подогнанному цилиндру, а не по «ребру» (раньше Ø
выходил больше на 8–35 мм) — двумя кликами верх/низ или новым инструментом **«Диаметр»** одним кликом; «Плоскость», «Отклонение», «Ребро/Угол» берут плоскость в окрестности клика, а не по всей сцене; значение на сцене
совпадает с числом в окне; Esc отменяет начатый замер, Backspace и Ctrl+Z — последнюю точку, Enter завершает ломаную/площадь; неготовый замер не сохраняется, «Очистить всё» при нескольких замерах просит подтверждения повторным нажатием.

## Автоматический замер объекта

В окне «Инспектор объекта» (**Измерения → Измерить объект →** рамка по объекту) вкладка «Автоматически» и кнопка **«Измерить автоматически»** сами находят размеры:
ширину, высоту и глубину проёма (двери, окна), толщину стены и перекрытия, высоту помещения, диаметр, уклон и высоту труб, расстояния между трубами, ширину лотка.
Каждый размер показан с погрешностью ±σ, способом и уровнем уверенности («высокая / средняя / низкая»); надёжные сохраняются в проект и сверяются с документацией,
сомнительные ждут вашего «Сохранить». Это оценка по облаку, а не гарантия: точность самого скана в ±σ не входит, скрытые работы не видны.

Замер идёт **именно по нужному объекту**: выбранный тип («Труба», «Проём»…) жёстко отсекает чужие находки, кнопка **«Указать объект»** привязывает замер к тому, по чему вы кликнули в облаке,
«Показать объект» рисует контур измеренного, а высота над полом выдаётся только при настоящем полу и никогда не сохраняется как размер объекта. Ложные «трубы» (огибающая пучка, земля, стена) отбрасываются, а в сводке
видно, сколько. Устройство, проверка на реальном скане и границы — [`AUTO-MEASURE.md`](AUTO-MEASURE.md).

## Бюджет точек: 200 млн

Минимум и значение по умолчанию для проекта — **200 млн точек** (`app-config.js`: `DEFAULT_MAX_POINTS`, `MIN_POINT_BUDGET`; потолок 300 млн). Если сохранённая настройка была ниже
(3 или 120 млн по умолчанию прежних версий), она **один раз поднимается до 200 млн**; значение, выбранное вручную ползунком «Плотность», сохраняется как есть (`pointBudgetCustom`).
Облако из файла читается целиком, пока в нём не больше точек, чем бюджет (скан на 49,8 млн точек читается полностью). Если свободной памяти на компьютере не хватает, чтение само
прореживается (не ниже 3 млн) и приложение сообщает об этом (`result.pointBudget.memoryLimited`) — вместо отказа по нехватке памяти. За один кадр на экран выводится не больше
80 млн точек (`LOD_DRAW_BUDGET`), для остального используется потоковая подгрузка; предел одного экранного буфера (96 млн) не менялся.

### Доля точек файла

По умолчанию облако открывается **целиком — 100 % точек файла**. Если нужно легче (слабый компьютер, быстрый просмотр), долю можно уменьшить: **Настройки → «Облака точек» → «Доля точек файла»**
(100, 50, 33, 25, 20, 10, 5, 2, 1 %) или в панели **«Вид облака» → «Доля точек»**; открытое облако тут же перечитывается. Оставляется одна точка из каждого блока по 1/k точек (`app-config.js`: `POINT_SHARES`,
`resolvePointShare`; `las-node.js`: `sampleStride`). Для E57 и для облаков, открытых «Потоковым LOD», доля не применяется. В свойствах облака «Загружено точек» показывает долю («31 550 (25 %)»).

Раньше основной процесс обрезал облако до 20 млн точек, чтобы передать его окну одним IPC-сообщением (`IPC_MAX_POINTS`), — отсюда «открыто 16 590 746 из 49 772 239». Этот предел **снят**: облако крупнее
`IPC_INLINE_POINTS` (6 млн) уходит в окно кусками по `IPC_CHUNK_POINTS` (4 млн) через `bim:readCloudChunk` и собирается в окне (`pending-clouds.js`, `renderer/cloud-chunks.js`). Если на компьютере не хватает
памяти окна, приложение сообщит об этом и предложит меньшую долю точек.

### Обработка облака

Лента **Облако → «Обработка»**: **Ресэмплирование** (случайно в процентах или по сетке в метрах), **Подавление шума** («летающие» точки; режим «Умный» смотрит на плотность места и удаляет только мелкие изолированные «острова» и одиночки, «Классический» — по числу соседей в радиусе), **Удалить людей** (поиск фигур по росту, ширине, опоре на землю и профилю «голова — торс — ноги»), **Сглаживание**
(проекция на локальную плоскость, рёбра и трубы сохраняются), **Выровнять поверхности** (стены, пол и потолок становятся ровными, двойные слои склеиваются), а также «Выровнять пол» и «Выровнять стену».
Расчёт идёт **в фоновом потоке** (`renderer/cloud-process.js`, `cloud-process-worker.js`): окно не замирает, виден прогресс, **Esc** или кнопка «Отмена» прерывает расчёт, облако при этом не меняется.
Результат отменяется **Ctrl+Z** (копий хранится 1–3 в зависимости от размера облака).

**Шум и люди — сначала покажем, потом удалим.** После расчёта «Подавление шума» и «Удалить людей» показывают найденное **красным поверх облака** и спрашивают подтверждение (плавающая панель: «Удалить N точек (x % облака)?», `Enter` — удалить, `Esc` — отмена; если находка больше 5 % облака, панель предупреждает). Облако до подтверждения не меняется; удаление отменяется **Ctrl+Z**.
Умный режим считает масштаб по месту (шаг точек у сканера растёт с расстоянием), поэтому не трогает редкие, но настоящие участки — дальние стены, провода, кроны. На синтетической уличной сцене с плотностью сканера (2,06 млн точек) прежний фильтр «радиус 0,2 м, 30 соседей» убирал 83,6 % шума,
но вместе с ним **17,4 % полезных точек**; умный «Средне» убирает ≈ 88 % шума и теряет **74 точки (0,004 %)**. Часть шума у краёв предметов («краевой ореол») остаётся — это честное ограничение; цифры и границы — [`RELEASE-1.2.0-rc.3.md`](RELEASE-1.2.0-rc.3.md), «Ревизия 7».
«Удалить людей» — эвристика: на тех же сценах находит 7–10 из 10 фигур и удаляет 96–99 % их точек, задевая 13–232 точки сцены (≤ 0,008 %); колонну, стойку, столбы, ящики, деревья и машины на уровне «Средне» не трогает; человек вплотную к стене или машине и полностью заслонённый могут остаться.

**Вид вблизи.** Размер точки при приближении берётся из **локального шага точек** (карта шагов считается в простое, 1 байт на точку), поэтому поверхность остаётся сплошной на любом удалении, а число точек не меняется — точки не исчезают и не «рассыпаются».

На синтетических сканах (шум 5–6 мм): сглаживание уменьшает шум стены с 6,3 до 0,8 мм, «Выровнять» сводит двойную стену с 30 до 1,2 мм, пол — до 0,02 мм; на облаке 20 млн точек
сглаживание ≈ 3 с, выравнивание ≈ 2,5 с, подавление шума (радиус 0,5 м, 30 соседей) ≈ 3 с. Среднее расстояние между плоскостями не смещается (≤ 0,05 мм), разброс замеров уменьшается. Мелкие трубы (R ≈ 10 см)
при малом радиусе сглаживания слегка «огранивает» — для диаметров используйте «Диаметр» и радиус от 0,06 м. Цифры и границы — [`RELEASE-1.2.0-rc.3.md`](RELEASE-1.2.0-rc.3.md), «Ревизия 6».

**Большие облака и лаги (ревизия 8).** При движении камеры окно само подбирает число рисуемых точек под 13 мс на кадр (случайная выборка из уже перемешанного буфера, размер точки компенсируется), через ≈ 160 мс после остановки рисуется всё облако.
Если файл не поместился в память целиком, после открытия предлагается «Показать все точки файла?» — запускается «Потоковый LOD»: индекс строится на диске по **всем** точкам (до 2 млрд; ≈ 1 млн точек/с и ≈ 19 Б/точку на диске в замере), на экране рисуется то, что нужно кадру.
Обычная загрузка использует весь бюджет памяти (дробный шаг выборки, а не «каждая 2-я/3-я»).

**Огромные облака: быстрый просмотр → все точки в фоне (ревизия 9).** Файл больше `STREAM_FIRST_POINTS` (50 млн точек, `app-config.js`) открывается за секунды как просмотр на `PREVIEW_POINTS` (6 млн) равномерно выбранных точек; индекс **всех** точек строится в фоне,
и вид сам переключается на потоковый режим (положение камеры сохраняется). Готовый индекс запоминается в каталоге данных приложения (`c-<отпечаток>`; ключ — путь, размер, время изменения файла и параметры; хранится `OCTREE_CACHE_KEEP` = 2 индекса, ≈ 20 Б/точку на индекс) — повторное открытие того же файла мгновенное.
Выключатели в настройках (`settings.json`): `streamFirst: false` — не использовать быстрый просмотр, `octreeCache: false` — не хранить индексы. В потоке точки выбираются по **экранной плотности** (`OctreeStore.selectLod`): узел уточняется, пока расстояние между его точками на экране больше ≈ 1 пикселя; в покое на экран выходит не больше 30 млн точек («Максимум» — 60 млн),
при движении — столько, сколько успевает видеокарта (не меньше 1,5 млн). Все точки остаются в индексе и показываются при приближении. Подробности и цифры — `RELEASE-1.2.0-rc.3.md`, «Ревизия 9». В «Выровнять поверхности» есть тип **«Фасад, стекло»** (толстый слой скана через стекло: доля точек в ±5 мм от плоскости на реальном фасаде 30–32 % → 87–94 %). Цифры и границы — [`RELEASE-1.2.0-rc.3.md`](RELEASE-1.2.0-rc.3.md), «Ревизия 8».

## Интерфейс

Рабочая область собрана по единой схеме: вкладки ленты (Проект · Импорт · Облако · Этажи · Измерения · Чертёж · BIM · Вид ·
3D-тур · Контроль · Экспорт), слева — дерево проекта, справа — инспектор, внизу — статусная строка; все команды также
доступны через палитру (`Ctrl K`). Стартовый экран показывает проекты карточками и открывает рабочую область с плавным
переходом. Принципы, токены, компоненты, API и способ проверки — в [`UI-DESIGN.md`](UI-DESIGN.md); визуальный стенд — в
[`dev/ui-lab`](dev/ui-lab/README.md).

## Фаза A — данные и постоянное хранение (готово)

- **Постоянное хранилище.** Два взаимозаменяемых бэкенда с одинаковым API:
  SQLite (`bim-twin.db`) или `store.json`. Оба в `userData` и переживают перезапуск.
- **Загрузка файлов.** Документы и 3D-модели копируются в `userData/uploads`.
- **Полный CRUD.** Кнопка «Правка» — добавление/изменение/удаление этажей, помещений, элементов и документов.
- **Резервное копирование.** Кнопка «Бэкап» — снимок данных в `backup-<ts>.json`.
- **Миграции.** SqliteStore безопасно добавляет новые колонки (schema_meta v2).

## Фаза B — Реальный 3D и IFC (v0.5)

Фаза B реализована **без внешних библиотек** (полностью оффлайн, без npm/CDN).

### B1. Настоящий 3D-движок (WebGL2)
Собственный движок `renderer/webgl-viewer.js` (`Viewer3DGL`): перспективная камера, орбита/панорамирование/зум, направленный и фоновый свет (GLSL 300 es), буфер глубины, покраска по типу/статусу НС, выбор кликом через CPU-raycast (Мёллер–Трумбор). Если WebGL2 недоступен — автоматический откат на canvas-2D `Viewer3D`.

### B2–B3. Импорт IFC и связь по GUID
Собственный парсер IFC (STEP / ISO-10303-21): `renderer/ifc-import.js` (браузер) и `db/ifcImport.js` (Node). Извлекает проект, этажи (IfcBuildingStorey), пространства (IfcSpace) и строительные элементы с их IFC GlobalId. Кнопка **«Импорт IFC»** сопоставляет GlobalId с `ifc_guid` в базе (связывание), а новые элементы создаёт. Пример файла: `ai/samples/building.ifc`.

> Геометрия IFC (BREP) не вычисляется — для этого нужен WASM-ядро web-ifc (требует установки через сеть). 3D-геометрия берётся из glTF/GLB (кнопка «Модель»).

### B4. Инструменты
- **Сечение** — горизонтальная плоскость отсечения (ползунок высоты).
- **Измерение** — расстояние между двумя точками (кликом).
- **Изоляция** — показать только выбранный элемент.
- **LOD** — упрощённая геометрия для тяжёлых glTF-моделей.

> Draco-сжатие glTF определяется, но требует кодека (установка через сеть). Несжатые .glb/.gltf работают напрямую.

## Фаза C — Настоящая проверка нейросетью (v0.6.0)

Настоящий разбор документов и нормоконтроль, без внешних зависимостей (только встроенные модули Node).

### Что добавлено

- **Разбор документов (`ai/parsers.js`)** — извлечение текста из `PDF`, `XLSX`, `CSV`, `TXT`.
  - XLSX/PDF распаковываются встроенным `zlib` (свой мини-ZIP-ридер + FlateDecode). Пакеты npm не нужны.
  - XLSX: поддержаны и `sharedStrings`, и `inlineStr`, декодируются XML-сущности (кириллица `&#NNNN;`).
- **OCR сканов (`ai/ocr.js`, C1)** — адаптер к локальному **Tesseract**. Если он установлен — сканы актов распознаются (`-l rus+eng`); если нет — модуль честно возвращает `tesseract_not_installed`, а проверка продолжается по текстовым документам и правилам.
- **Движок проверки (`ai/verify.js`, C2/C3)** — правила нормоконтроля: сечение воздуховода (проект vs модель), перегрузка перекрытия, отклонение площади остекления, класс огнестойкости двери, покрытие элемента документами. Каждая находка со степенью (`err/warn/ok`) и уверенностью.
- **LLM-верификатор (`ai/llm.js`, C3)** — опциональная эскалация спорных находок в LLM: **OpenAI** (`gpt-4o-mini`) или **Ollama** (`llama3.1`). Удалённый провайдер требует явного согласия и ограничивает передаваемый контекст. Без ключа шаг пропускается — приложение полностью работает офлайн.
- **Ревью находок (C4)** — по каждой находке: **Принять / Отклонить / Комментарий**. Отклонённые находки не влияют на статус элемента. Состояние ревью и комментарии сохраняются и **переносятся при повторном анализе**.
- **Повторный анализ при загрузке** — при включённой «Авто-проверке» загрузка нового документа сразу запускает проверку помещения.
- **Настройки ИИ** — LLM-провайдер, ключ/хост/модель, лимит контекста, согласие на удалённую обработку, язык OCR и авто-проверка. Ключ не возвращается renderer и сохраняется только через системное защищённое хранилище; при недоступном `safeStorage` plaintext не сохраняется.

### Как пользоваться

1. Откройте помещение → загрузите документы (кнопка **Документ**): смета `.xlsx/.csv`, чертёж-заметки `.txt`, чертёж `.pdf`, скан акта `.png/.jpg`.
2. Нажмите **Проверить НС** (в тулбаре) или **⟳ Проверить помещение** на вкладке «Нейросеть».
3. Разберите находки: **Принять/Отклонить/Комментарий**. Статусы элементов в дереве и 3D обновятся.
4. Для сканов установите Tesseract (`tesseract-ocr` + языковые пакеты `rus`, `eng`). Для LLM укажите ключ в **Настройки ИИ**.

> Демо-версия в браузере выполняет проверку по проектному замыслу (без разбора файлов). Полный разбор PDF/XLSX/OCR и ревью с сохранением доступны в десктоп-сборке.

### Изменения в данных

- `ai_findings` расширена: `review`, `source`, `comments` (JSON), `created_at`.
- Новая таблица/секция `settings`. Миграция выполняется автоматически (`schema version 3`).

## Фаза D — командная работа (v0.7.0)

- **D1. Мультипроектность.** Переключатель проектов в боковой панели + кнопка «＋» для создания. Каждый проект хранит свои этажи/помещения/находки; переключение сохраняет состояние (в JSON — через архив проектов, в SQLite — через `activeProjectId` и фильтрацию по проекту).
- **D2. Пользователи и роли.** Кнопка «Команда»: добавление/редактирование/удаление участников с ролями (Администратор / Инженер / Наблюдатель). На карточке находки — кнопка 👤 «Назначить ответственного» и срок; ответственный отображается на карточке.
- **D3. Обсуждения по элементу (BCF-подобно).** Вкладка «Обсуждения» в инспекторе: темы привязаны к выбранному элементу, есть комментарии, статусы «открыто/решено», удаление. При удалении элемента связанные обсуждения очищаются.
- **D4. Экспорт отчётов.** Кнопка «Экспорт»: область (весь проект / текущее помещение) и формат:
  - **CSV** — с BOM и разделителем `;` (корректно открывается в Excel, полная кириллица);
  - **HTML** — печать в PDF из браузера (Ctrl/Cmd+P), полная кириллица, сводные карточки;
  - **PDF** — нативная генерация без внешних зависимостей (кириллица транслитерируется в латиницу, т.к. базовые шрифты PDF без кириллицы).
  В десктоп-версии файл сохраняется через системный диалог; в демо-режиме CSV/HTML скачиваются через браузер.
- **D5. Синхронизация команды.** Кнопка «Синхр.»: потоковый hash-verified `.bimsync` со staging, лимитами и транзакционным импортом/rollback. Legacy JSON-пакеты читаются только после строгой проверки имён, размеров и base64. Обмен через общий диск/облако вручную (без сервера).

Модуль отчётов: `ai/report.js` (`build`, `buildRows`, `toCSV`, `toHTML`, `toPDF`, `translit`). Тесты Фазы D — в `db/_test.js` (проекты, пользователи, назначение, обсуждения, отчёт, round-trip синхронизации).

## Фаза E — дистрибуция и UX (v0.8.0)

- **E1. Автообновления** — `electron-updater` подключается безопасно (try/catch), проверка только в установленной сборке (`app.isPackaged`). Кнопка «Проверить обновления» в настройках. Канал обновлений настраивается в `build.publish` (`package.json`) — замените `url` на ваш сервер/релизы.
- **E2. Подпись установщиков** — конфиг `build.win` / `build.mac`. Подпись выполняется на этапе сборки:
  - **Windows:** задайте переменные окружения `CSC_LINK` (путь/URL к `.pfx`) и `CSC_KEY_PASSWORD`, либо укажите `certificateSubjectName` для хранилища сертификатов.
  - **macOS:** задайте `CSC_LINK`/`CSC_KEY_PASSWORD` (Developer ID) и переменные для нотаризации (`APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, `APPLE_TEAM_ID`).
  - Без сертификатов сборка создаёт неподписанные установщики (для тестов).
- **E3. Экран настроек** — полноценное окно: тема (светлая/тёмная), язык, настройки ИИ (провайдер/ключ/хост/модель/OCR/авто-проверка), пути к данным (только чтение, с кнопкой открытия папки), версия и проверка обновлений.
- **E4. Локализация (RU / UA / EN)** — `renderer/i18n.js`, словари для трёх языков, переключение на лету через `data-i18n` / `data-i18n-ph` / `data-i18n-title`. Выбор языка сохраняется.
- **E5. Онбординг + демо-проект** — приветственный экран при первом запуске (выбор языка, обзор возможностей) и кнопка «Загрузить демо-проект» (создаёт проект с этажом, помещениями и элементами). Флаг пройденного онбординга сохраняется.

Запуск сборки с публикацией обновлений: `npm run publish` (после настройки `build.publish` и сертификатов).

## Быстрая установка (авто-скрипты)

В корне проекта есть скрипты, которые ставят все компоненты для полной работы (база, SQLite, IFC, Tesseract OCR, Ollama):

- **Windows:** дважды кликните `setup.bat` или выполните `setup.bat all` (без вопросов). Альтернатива — PowerShell:
  ```powershell
  powershell -ExecutionPolicy Bypass -File .\setup.ps1        # интерактивно
  powershell -ExecutionPolicy Bypass -File .\setup.ps1 -All   # всё сразу
  ```
- **macOS / Linux:**
  ```bash
  chmod +x setup.sh
  ./setup.sh        # интерактивно
  ./setup.sh all    # всё сразу
  ```

Скрипты проверяют Node.js, ставят npm-зависимости и по желанию — SQLite (`better-sqlite3`), IFC (`web-ifc`, `draco3d`), Tesseract OCR с языками **rus + ukr + eng** и Ollama (локальный LLM `llama3.1`). Опциональные шаги не прерывают установку при сбое.

### Языки и модели
- **Интерфейс:** русский / украинский / английский (переключается в Настройках).
- **OCR (Tesseract):** поддерживает украинский через пакет `ukr`; значение по умолчанию — `rus+ukr+eng`.
- **LLM:** GPT-4o-mini и Ollama понимают украинский; язык ответов следует языку документов/запроса.
