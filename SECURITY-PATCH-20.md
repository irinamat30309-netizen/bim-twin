# Patch 20 — Бэклог аудита: миграции БД, валидация IPC, тесты + CI

Дата: 2026-08-24. Версия приложения: 0.9.39.
Продолжение аудита (patch 18 — безопасность, patch 19 — производительность). Здесь закрыты три пункта бэклога, которые можно внедрить и проверить без запуска Electron.

## 1. Явные версионированные миграции БД

**Проблема.** `db/schema.sql` при каждом старте выполнял `INSERT OR REPLACE ... VALUES ('version','2')`, то есть сбрасывал записанную версию схемы обратно на 2. Метод `_migrate()` в `db/sqliteStore.js` был «плоским»: гонял все `ALTER TABLE`/`CREATE TABLE` при каждом запуске и в конце жёстко ставил версию `4`. Реальная версия схемы не отслеживалась, добавить новый шаг миграции безопасно было нельзя.

**Что сделано.**
- `db/schema.sql`: `INSERT OR REPLACE` → `INSERT OR IGNORE` для строки версии — начальная версия ставится один раз и больше не перетирается.
- `db/sqliteStore.js`: добавлены `_schemaVersion()` и `_setSchemaVersion(v)` (чтение/запись версии в таблице `schema_meta`).
- `_migrate()` переписан как **лестница миграций**: массив шагов `{ v, up }`. Применяются только шаги, у которых `v` больше текущей версии; каждый шаг выполняется в транзакции (`this.db.transaction(up)()`), после успеха версия повышается.
  - `v3`: колонки `rooms.model_*`, `documents.*`, `ai_findings` (review/source/comments/created_at), таблица `settings`.
  - `v4`: `ai_findings` (assignee/due), таблицы `users`, `discussions`.
- Все шаги идемпотентны (`_ensureColumn` + `CREATE TABLE IF NOT EXISTS`), поэтому на уже мигрированных базах повторный прогон безопасен, а новые версии добавляются просто новым элементом массива.

**Эффект.** Предсказуемые, отслеживаемые обновления схемы; отсутствие лишних DDL на каждом старте; безопасная площадка для будущих миграций.

## 2. Валидация входных данных IPC (main-процесс)

**Проблема.** IPC-обработчики `bim:*` передавали аргументы из renderer напрямую в хранилище (`store.updateRoom(a.id, a.patch)` и т.п.) без проверки типов. Некорректный/повреждённый payload мог вызвать неожиданное поведение хранилища. Обработчик `bim:parseCloud` читал с диска путь любого расширения.

**Что сделано (`main.js`).**
- Добавлены валидаторы: `vId` (непустая строка), `vStr` (строка), `vPatch` (объект или null, не массив), `vArgs` (объект аргументов, не массив).
- Валидацией обёрнуты ~26 обработчиков CRUD: этажи, помещения, элементы, документы, находки, проекты, пользователи, обсуждения, назначения. Комбинированные обработчики переведены в блочную форму с проверкой `id`/`patch`; `setDiscussionStatus` проверяет `status` строкой; `analyzeRoom` проверяет `roomId`.
- `bim:parseCloud`: добавлен белый список расширений `CLOUD_EXT_ALLOW` (`.las/.laz/.ply/.e57/.pcd/.xyz/.pts/.xyzrgb`); недопустимое расширение → `{ ok:false, message:'ext_not_allowed' }` (симметрично `PICKED_EXT_ALLOW` из patch 19).
- Свободные текстовые комментарии (`addFindingComment`, `addDiscussionComment`) осознанно не ограничиваются по типу — их обработка на стороне хранилища уже приводит значение к строке.

**Эффект.** Некорректные аргументы отсекаются на границе main-процесса, до обращения к данным на диске.

## 3. Юнит-тесты + CI

**Проблема.** В проекте был только один ручной скрипт `db/_test.js`; автоматических тестов и CI не было.

**Что сделано.**
- `test/store.test.js` — `node:test`: сид, CRUD + персистентность после перезагрузки, backup roundtrip, изоляция проектов и переключение.
- `test/verify.test.js` — движок нормоконтроля `ai/verify.js`: `extractDims/extractFire/extractDiam`, `num`, `statusOf`, правила `verifyElement` (расхождение сечения, перегрузка перекрытия, покрытие документами) и `verifyRoom`.
- `test/report.test.js` — генератор отчётов `ai/report.js`: BOM+utf8 в CSV, сигнатура `%PDF-`, заголовок в HTML.
- `package.json`: скрипты `test` (`node --test`), `test:store`, `check` (синтаксис ключевых файлов).
- `.github/workflows/ci.yml`: Node 20 на ubuntu — `node --check` ключевых файлов + `node --test`. Тесты используют только встроенные модули Node и чистые локальные модули, поэтому CI не требует установки нативных/внешних зависимостей (`better-sqlite3`, Electron).

**Результат прогона:** `node --test` → **18 pass / 0 fail**. `node --check` main.js/preload.js/sqliteStore.js/jsonStore.js — без ошибок.
